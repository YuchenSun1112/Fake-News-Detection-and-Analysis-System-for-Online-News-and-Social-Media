\noindent\textbf{Abstract}: This report describes a fake-news detection and evidence-based news verification prototype for online news and social media content. The original project proposal focused on offline text analysis: a BERT fake/real classifier, topic modeling, sentiment analysis, and a Streamlit interface. After project feedback, the design was revised because judging only by writing style or offline textual patterns is not sufficient for factual verification. The implemented system therefore keeps BERT as a baseline signal, but extends the solution with claim extraction, live evidence retrieval, evidence comparison, and article-level verdict aggregation.

\smallskip
\noindent\textbf{Keywords}: BERT Classification, Claim Extraction, Evidence Retrieval, Evidence Comparison

\section{The Business Problem}

Online news and social media platforms spread information quickly, but users do
not always have an efficient way to check whether a news item is factually
supported. A misleading article may use credible language while still making
claims that are unsupported, contradicted, or unverifiable.

The initial proposal treated fake-news detection mainly as an offline NLP
classification problem. In that framing, the system learns textual patterns from
labeled examples and predicts whether a new article looks fake or real. This is
useful as a screening signal, but it has three important weaknesses:

\begin{itemize}
    \item it may learn writing style, source patterns, or topic bias instead of
    verifying factual correctness;
    \item it cannot explain which claims in the article are true, false, or
    unsupported;
    \item it struggles with real-world cases where a well-written article
    contains a few false factual claims.
\end{itemize}

Based on this limitation, the business problem was refined from ``classify
whether the text looks fake'' to ``help users verify whether important claims in
the article are supported by external evidence.'' The system should:

\begin{itemize}
    \item classify whether a news item appears fake or real based on labeled
    training data;
    \item extract factual claims from the submitted article;
    \item retrieve external evidence related to each claim through search;
    \item compare each claim with retrieved evidence and show whether the
    evidence supports, refutes, or cannot verify it;
    \item provide an interpretable article-level verdict rather than only a
    black-box prediction.
\end{itemize}

The intended users are students, researchers, journalists, and general readers
who need an explainable first-pass news verification tool. The prototype is not
designed to replace professional fact-checking, but to demonstrate how machine
learning and evidence retrieval can support more transparent verification.

files follow the minimal FakeNewsNet-style structure for the GossipCop and

\section{The Solution Approaches}

The implemented solution evolved from the original offline NLP plan into a
hybrid system with two complementary parts: a baseline supervised classifier and
an evidence-based verification pipeline.

\subsection{Design Evolution from the Proposal}

The proposal contained three offline analysis modules: fake-news classification,
topic modeling, and sentiment analysis. The revised design keeps the fake/real
classifier, but changes the supporting modules. Topic and sentiment can describe
an article, but they do not verify factual claims. For example, an article can
have a neutral sentiment and a clear political topic while still containing
false numbers, fabricated events, or misleading attributions.

Therefore, the final direction prioritizes search and comparison. The key
change is that the system no longer treats the input text alone as the only
evidence. Instead, it extracts factual claims, searches for related external
news, compares the claim with retrieved evidence, and then explains the final
verdict.

\subsection{Baseline Fake/Real Classification}

The baseline classifier is implemented in the \code{baseline\_model.py} module.
It fine-tunes \code{bert-base-uncased} for binary sequence classification. The data
loader combines the news title and cleaned text into a \code{final\_text} field
and assigns label \code{1} to real news and label \code{0} to fake news. The
training code uses an 80/20 train-test split, stratification by label, three
training epochs, early stopping, and standard classification metrics: accuracy,
precision, recall, and F1.

In the revised system, this classifier is intentionally treated as a baseline
rather than the whole decision mechanism. Its role is to estimate whether the
article resembles fake or real examples in the offline dataset. The evidence
pipeline then checks whether the article's factual claims can be supported by
external sources.

\subsection{Evidence-based Claim Verification}

The second approach is designed to make the system more explainable. Instead of
only returning a fake/real prediction, the application performs claim-level
verification:

\begin{enumerate}
    \item \textbf{Text cleaning:} \code{src/cleaner.py} normalizes user input.
    \item \textbf{Claim extraction:} \code{src/claim\_extractor.py} splits the
    article into chunks, filters weak or subjective statements, and selects
    factual claims containing entities, dates, numbers, or event verbs.
    \item \textbf{Evidence retrieval:} \code{src/retriever.py} builds several
    search queries per claim, calls the GNews API, deduplicates retrieved
    articles, and ranks evidence using title overlap, text overlap, entity
    matches, number matches, and API rank.
    \item \textbf{Claim verification:} \code{src/verifier.py} assigns one of
    three labels using token overlap, number consistency, and negation/polarity
    signals: \code{supported}, \code{refuted}, or \code{not enough information}.
    \item \textbf{Final aggregation:} \code{src/aggregator.py} combines
    claim-level labels and confidence scores into \code{Likely True},
    \code{Likely False}, or \code{Unverified}.
\end{enumerate}

\subsection{User Interface}

The Streamlit application in \code{app.py} exposes the full workflow. It shows
the baseline classifier result, extraction progress, claim-level retrieval
queries, best evidence, verification labels, confidence values, and final
verdict. This interface is important because the project goal is not only
prediction accuracy, but also interpretability.

\subsection{Evaluation Implications of the Revised Design}

The proposal evaluation plan focused on classifier metrics such as accuracy,
precision, recall, F1, and confusion matrices. Those metrics remain necessary
for the BERT baseline, but they are no longer sufficient for the full system.
Because the system now performs search and evidence comparison, evaluation
should also check whether retrieved evidence is relevant and whether the
claim-level labels are correct.

A complete evaluation should therefore include:

\begin{itemize}
    \item \textbf{Baseline classification performance:} accuracy, precision,
    recall, F1, and confusion matrix on held-out title/article examples.
    \item \textbf{Claim extraction quality:} whether extracted claims are
    factual, specific, non-duplicate, and searchable.
    \item \textbf{Retrieval quality:} whether top-ranked GNews results are
    actually related to the claim.
    \item \textbf{Comparison quality:} whether the verifier correctly assigns
    supported, refuted, or not-enough-information labels.
    \item \textbf{End-user usefulness:} whether the displayed evidence makes the
    final verdict understandable to users.
\end{itemize}

\section{Conclusions}

The project implements a practical and explainable prototype for fake-news
detection and factual verification. The baseline BERT classifier provides a
fast fake/real signal from title-level labeled data, while the claim-level
pipeline improves transparency by showing extracted claims, retrieval queries,
evidence snippets, verification labels, and the reasoning behind the final
verdict.

Compared with the proposal-stage design, the final system better addresses the
project feedback that a purely offline fake-news classifier is incomplete.
Offline classification can identify suspicious writing patterns, but factual
verification requires checking claims against external information. The revised
system therefore moves from style-based detection toward evidence-based
verification.

The main conclusion is that the system design is more informative than a single
black-box classifier, but the current repository should be presented as an
implemented prototype rather than a fully validated production system. The next
required step is to run baseline training, save the evaluation metrics, and
create a manually labeled claim-evidence test set for the verification pipeline.
